# Invariant 1.1.0 verification (5 November 2026)

Work starts from `7961f17` (`origin/claude/adoring-gates-2zcqkm`), the
latest v1.0 development snapshot found on the remote. It is isolated in
`codex/v1.1-fixes`; no merge into `main` was performed.

## Changes

- Added CLI SARIF 2.1.0 output and combinable rule-list filters.
- Fixed global/nonlocal call resolution, malformed webhook signatures,
  invalid GitHub paths/names, database integer bounds and unsafe retry delays.
- Fixed worker/comment crashes when projects are deleted and preserved the
  queued repository identity across project reconfiguration.
- Limited persisted rule violations to 1,000 without changing full counts or
  verdicts. This integrates the existing diagnostic-cap work from `e0b99ac`.
- Repaired Windows test harness assumptions about UTF-8, Bash and shell commands.

The fixes also cover defects documented in the historical
[v1.0 audit](2026-10-24-v1.0-release-readiness.md). That report remains a record
of the earlier snapshot, rather than the status of this branch.

No database schema change or new runtime dependency is required from 1.0.0.

## Boundaries and manual review

- GitHub HTTP calls and webhook deliveries were simulated. No real pull
  request, comment or GitHub code-scanning upload was created.
- Review the new CLI format and rule filters, plus the documented cap:
  diagnostic pagination counts stored rows, while summary counts include
  omitted violations. A checker's temporary per-file findings are not capped.
- This remains a deterministic Python analyzer with the limitations documented
  in the README; it does not prove runtime behavior.
- Tests used a separate Compose project, database volume and loopback ports
  `18011`/`55433`; the prior project's database was preserved.
