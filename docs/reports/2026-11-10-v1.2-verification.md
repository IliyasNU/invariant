# Invariant 1.2.0 verification (10 November 2026)

This increment starts from `e1057d5` on `codex/v1.1-fixes`. It adds a stored-run
SARIF export and fixes GitHub input/configuration handling. The framework,
database schema and runtime dependencies are unchanged. No merge into `main`
was performed.

## Behavior

- `GET /analysis-runs/{id}/sarif` requires the API key and downloads a SARIF
  2.1.0 document. The recorded configuration, diagnostic snapshots and engine
  version are used, so changing or deleting live rules does not change history.
- Summary counts include omitted violations. A capped listing is identified
  explicitly by omitted counts, a truncation property and a warning notification.
  Actual analysis errors remain unsuccessful invocation notifications.
- Queued, running and failed runs return `409 analysis_not_completed`; legacy
  runs without supported snapshots/complete metadata return
  `409 sarif_unavailable`. Their existing JSON history remains accessible.
- Webhook signatures use the receiving app's configured secret. Two apps can
  have separate secrets even in one process. Process-environment changes after
  app creation no longer change a running app's signature verification.
- Malformed Content-Length headers, very large decimal lengths, deep JSON and
  invalid changed-file statuses are handled as structured GitHub errors.

verified 1,000 listed results, full summary counts, five omitted errors,
the truncation warning, unsuccessful analysis notification, download media
type and producer version. The same report was returned after deleting the
original rule. Existing JSON export and valid/invalid HMAC deliveries were
also checked. Only the generated smoke-test project/history was removed.

SARIF was validated with Draft4Validator and URI format checking against the
[official OASIS 2.1.0 schema](https://docs.oasis-open.org/sarif/sarif/v2.1.0/errata01/os/schemas/sarif-schema-2.1.0.json).

environment, not added to project dependencies.

The full PostgreSQL run includes migration and worker-concurrency coverage.
Three tests are skipped on Windows for POSIX-only filenames. SQLite skips
four additional PostgreSQL-only tests. The wheel remains pure Python and
does not include the server or native benchmark binaries.

## Local execution

Tests used the previously created disposable PostgreSQL cluster under
`outputs/postgres-v111-final-20261109`, on `127.0.0.1:55434`, with new isolated
databases `invariant_v12_app` and `invariant_v12_tests`. The native installed
PostgreSQL 18 binaries were used; this increment did not rebuild/test Docker
containers. Docker definitions and migrations were unchanged.

Representative commands from the release checkout:

```powershell
uv sync --frozen --dev
uv run pytest -p no:cacheprovider --basetemp=../../outputs/pytest-v12-sqlite
$env:INVARIANT_TEST_DATABASE_URL = 'postgresql+psycopg://invariant@127.0.0.1:55434/invariant_v12_tests'
uv run pytest -p no:cacheprovider --basetemp=../../outputs/pytest-v12-postgres
Remove-Item Env:INVARIANT_TEST_DATABASE_URL
uv run ruff check app benchmarks examples migrations scripts src tests
uv run ruff format --check app benchmarks examples migrations scripts src tests
uv run python -m compileall -q app migrations scripts src tests
uv run invariant check .
uv build
```

The PostgreSQL URL must identify a disposable database: tests recreate its
schema. No existing application database was used.
